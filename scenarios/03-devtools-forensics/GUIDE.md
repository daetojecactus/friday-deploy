# Гайд для команды — DevTools Forensics

Короткий рассказ: что происходит и что от вас нужно. Читается за три минуты —
этого достаточно.

---

## Что происходит

Есть телеграм-бот **ReportDailyBot**: он сам собирает вашу активность из GitLab и
вечером присылает готовый отчёт в Telegram. У бота есть внутренний контур —
консоль владельца, очередь рассылки, шлюз к GitLab, телеметрия, статус выката.
Всё это живёт за VPN и наружу смотреть не должно.

А ещё у бота есть публичный лендинг. Тот самый, со скидкой −146%, бегущей
строкой и танцующим бананом. Писали его в угаре, и вместе с «КУПИ СЕЙЧАС ИЛИ
ЖАЛЕЙ ВСЮ ЖИЗНЬ» на страницу переехали куски админки.

Сегодня утром пришёл отчёт внешнего аудита: внутренние адреса бота выяснили, не
выходя из браузера. Ни одного эксплойта, ни одного сканера — только F12.

**Ваша задача — найти всё, что светит внутренний контур.** Пятнадцать точек.

---

## Правила

1. **Работаем только в браузере.** Chrome DevTools — единственный инструмент.
   `curl` можно, если захочется постучаться в найденный адрес.
2. **Репозиторий не открываем.** В нём лежат ответы — открыть его значит
   закончить игру.
3. **Ничего не чиним.** Задача — найти, а не починить. Разбор «как надо было» —
   после каждой находки.
4. **Диктует Капитан.** Нашли адрес — говорите вслух, ведущий вводит его в свой
   дашборд. Совпало — загорается зелёная лампочка.

---

## Что считается находкой

**Адрес** внутреннего контура, который вы нашли на публичной странице: путь
вида `/что-то/там-эдакое-a1b2`. Каждый такой адрес — рабочий, откройте его и
посмотрите, что за ним лежит.

Что находкой **не** считается:

- имя домена само по себе — оно светится почти везде и ни на что конкретное не
  указывает;
- общий кусок пути без хвоста — это правильное направление, но ещё не адрес.

Токены и имена серверов, которые попадутся по дороге, — это не ответ, а
доказательство: их стоит назвать вслух на разборе, но в зачёт идёт адрес.

Форма записи не важна: полный URL, голый путь, строка с кавычками из JSON — всё
приводится к одному виду. Диктуйте как видите.

---

## С чего начать

Открывайте страницу, жмите F12 и идите по панелям. Каждая утечка живёт в своей —
Elements, Network, Application, Console, Sources. Если в какой-то панели вы ещё
не были, скорее всего там что-то есть.

Полезное, о чём часто забывают:

| Приём | Зачем |
| --- | --- |
| Фильтры в Network (`Fetch/XHR`, `Img`, `CSS`, `Doc`) | разделить сорок запросов по типам |
| Колонка **Domain** в Network | видно, какой запрос ушёл не на этот сайт |
| Вкладки **Headers** и **Response** у запроса | это два разных места, и смотреть надо оба |
| **Preserve log** | без него переход по ссылке стирает всё, что было до него |
| **Ctrl+Shift+F** в Sources | глобальный поиск по всем файлам, включая бандл |
| Дерево файлов в **Sources** | иногда там лежит больше, чем вы выкладывали |
| Вкладка **Application** | localStorage, cookies, session storage |
| **Console** без единой команды | там уже что-то написано, просто прочитайте |
| `Object.keys(window)` в Console | что страница положила в глобальную область |
| Панель **Styles** у элемента | почему элемент есть в разметке, но не на экране |
| Тег **`<head>`** в Elements | все смотрят `<body>`, а туда сборка тоже что-то пишет |
| Файлы по фиксированным адресам | у любого сайта они есть, и открыть их может каждый |

Сложность каждой утечки ведущий видит у себя в звёздах и подскажет, если вы
взялись за самое тяжёлое первым. Если совсем встали — просите подсказку: она
придёт ответом в рабочий чат, и первая ничего не выдаёт, а просто говорит, когда
эта утечка вообще видна.

---

## Чего ждать

Ничего не «зеленеет» само. Обратная связь приходит от ведущего: он вводит ваш
адрес, и в чат #security падают два сообщения — ИБ объясняет, почему эта строка
вообще оказалась на публичной странице, а тимлид говорит, чем это грозит.

Разбор и есть смысл упражнения. Найти — половина дела, вторая половина — понять,
каким образом это туда попало.

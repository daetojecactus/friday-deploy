# CONTEXT — DevTools Forensics

Единый контекст стенда №03: философия, интерфейс, архитектура, реестр утечек,
механика зачёта и правила разработки. Документ рассчитан и на человека, и на
ИИ-ассистента, который помогает с этим проектом.

Эталон стиля — [`scenarios/02-mongodb-dubug`](../02-mongodb-dubug/CONTEXT.md).
Отличие принципиальное: там чинят базу, здесь **ничего не чинят вообще** —
ищут. Инструмент один: Chrome DevTools.

---

## 1. Цель и философия

**ReportDailyBot** — телеграм-бот, который сам собирает активность из GitLab и
отправляет ежедневный отчёт в Telegram. У бота есть внутренний контур:
GitLab API, Telegram Bot API, AI-провайдеры, очередь рассылки, консоль
владельца, статус выката.

И есть публичный лендинг — тот самый, с кислотным маркетингом, бегущими
строками и скидкой −146%. Писали его в угаре, и вместе с «КУПИ СЕЙЧАС ИЛИ ЖАЛЕЙ
ВСЮ ЖИЗНЬ» на него переехали куски админки: прямые ссылки на внутренний контур,
токены бота, служебные заголовки, забытый старый бандл с картой исходников.

От отдела ИБ пришёл сигнал: внутренние адреса выяснили, не выходя из браузера.
Участник проводит ревизию — проходит по лендингу и находит все точки утечки.

Четыре правила, которые определяют весь дизайн стенда:

1. **Команда не получает репозиторий.** Только ссылку `http://<ip>:8080` и
   браузер. Репозиторий — это ответ: в нём и сайт с утечками, и реестр
   маркеров. Ключевое отличие от 01 и 02, где команда работала внутри кодовой
   базы.
2. **Ничего не чинится.** Стенд не «зеленеет» сам. Прогресс двигает ведущий,
   который вводит найденные адреса в свой дашборд под диктовку Капитана.
3. **Каждая утечка живёт в своей панели DevTools.** Elements, Network,
   Application, Console, Sources — пятнадцать кейсов покрывают все пять, а
   внутри Network расходятся по разным вкладкам и режимам. Учим инструменту, а
   не пятнадцати вариациям одного приёма.
4. **Шум — несущая конструкция, а не украшение.** Сорок запросов в Network,
   девять ключей в localStorage, минифицированный бандл, ложные следы. Без них
   игра кончается за семь минут.

Кислотная эстетика лендинга — не шутка ради шутки, а рабочий инструмент: на
странице, где всё мигает и крутится, найти одну лишнюю ссылку объективно
труднее. Визуальный шум работает на задачу.

## 2. Интерфейс

Стенд — это две страницы для двух разных людей.

### Публичный лендинг (команда) — http://\<ip\>:8080

`!!!$$$ КУПИ REPORTDAILYBOT СЕЙЧАС $$$!!!` — одностраничник в лучших традициях
навязчивого маркетинга: Comic Sans, радужный фон, `<marquee>`, мигающий ценник,
попап «скидка сгорит через 00:59». Никаких признаков игры на нём нет — ни
счётчиков находок, ни подсказок, ни упоминания стенда.

| Блок | Что в нём | Утечки |
| --- | --- | --- |
| Бегущая строка | `<marquee>` «ЛУЧШЕЕ ПРЕДЛОЖЕНИЕ В ИСТОРИИ ЧЕЛОВЕЧЕСТВА» | — |
| Hero | логотипы, заголовок, ценник −146%, фон «наш дата-центр» | 3 |
| Кнопка «ХОЧУ СЕЙЧАС» | ведёт на страницу акции | 8 |
| Счётчик отчётов | «отправлено сегодня», грузится XHR | 5 |
| Виджет очереди | не отвечает, обработчик ошибки пишет в консоль | 15 |
| Преимущества | три карточки в разметке, ещё три дорисовывает JS | — |
| Демо отчёта | три шаблона бота (Standard/QA/SA), переключаются | — |
| Отзывы клиентов (REAL!) | грузятся XHR | 9 |
| Тарифы, FAQ, партнёры | контент, шум в Network | — |
| Форма «ОСТАВЬ ЗАЯВКУ» | `<form action>` | 1 |
| Футер, скрытый блок | «ПАНЕЛЬ ВЛАДЕЛЬЦА», спрятана классом в CSS | 2 |
| Невидимое | конфиг, localStorage, cookie, бандлы, заголовки, robots.txt | 4, 6, 7, 10, 11, 12, 13, 14 |

**Таблица ничего не выдаёт заранее.** До находки строка называет только номер и
звёзды: название вроде «Runtime Config» — это половина ответа, и держать его на
виду весь урок нельзя. Категория, адрес и разбор появляются в момент, когда
утечку закрыли. Ненайденные маркеры не уезжают с сервера вообще, поэтому
дашборд не спойлерит даже случайно.

**Звёзды видны сразу** и решают отдельную задачу: джун не должен нырять в
трёхзвёздочный хардкод в минифицированном бандле, пока не взял пару лёгких.
Ведущий смотрит на звёзды и направляет.

**Статус** — зелёная лампочка с временем находки. Пока не найдено — серая, и
рядом две кнопки: `[?]` подсказка и `[!]` ответ. Значок 💡 показывает, сколько
подсказок уже выдано, а в найденной строке — что её взяли с подсказкой.

### Подсказки — это переписка, а не всплывающее окно

Нажатие `[?]` не открывает модалку, а пишет в чат от лица команды: «Застряли на
утечке №4, её видно сразу или нужно что-то сделать?» — и ИБ отвечает
направлением. Ведущему остаётся зачитать.

Так подсказка перестаёт быть служебной кнопкой и становится частью истории: в
ленте виден живой след того, где команда буксовала, и его удобно разбирать в
конце. Три уровня:

| Уровень | О чём | Пример (утечка 4) |
| --- | --- | --- |
| L1 | когда и при каком действии видно | «появляется при первом рендере и переживает перезагрузку» |
| L2 | какая панель DevTools | «Application → Local Storage: ключей там больше, чем нужно лендингу» |
| L3 | что именно смотреть | «одно значение выглядит как мусор — это не мусор, а кодировка» |

**Кнопка `[!]`** — за подтверждением, раскрывает маркер и закрывает утечку как
нерешённую. Нужна, когда время вышло.

### Чат #security и две реплики на находку

Каждая находка даёт в ленту **две** реплики, и это разные роли:

- **Тринити (ИБ)** объясняет, почему это вообще утечка: «CSS убирает элемент с
  экрана, но не из исходника».
- **Уинстон Вульф (тимлид)** называет цену вопроса: «за ссылкой лежит консоль
  владельца со списком пользователей бота и их Telegram ID».

Разделение намеренное: механика и последствия — разные разговоры, и звучат они
из разных ртов. Это и есть учебная ценность стенда.

### Почему чат читается как чат

Четыре приёма, которые отличают ленту от лога:

1. **Реплики приходят по очереди, а не пачкой.** У каждого сообщения есть
   `publishAt`, и наружу оно уезжает, когда время подошло: тимлид отвечает через
   1,2 секунды после ИБ, ответ на просьбу о подсказке — через секунду. Пауза
   отсчитывается от предыдущего запланированного сообщения, поэтому две реплики
   подряд не схлопываются в одну.

   Паузы намеренно короткие. Их задача — только развести реплики по времени,
   чтобы было видно очередь и «кто печатает»; всё остальное время ведущий ждёт
   зря. Раньше здесь стояли 3,5–5 секунд, и одно вступление занимало
   13 секунд — сейчас те же четыре реплики укладываются в 3,5.
2. **Видно, что кто-то печатает.** Дашборд знает автора ближайшего
   неопубликованного сообщения и показывает «Уинстон Вульф печатает…» с
   набегающим троеточием. Опрос идёт раз в 0,6 секунды: при паузах около секунды
   более редкий поллинг был бы заметнее самой паузы.
3. **Формулировки не повторяются.** Просьба о подсказке написана в трёх вариантах
   на каждый уровень: одна и та же фраза в пятый раз убивает ощущение живого чата
   быстрее всего.
4. **Коллеги подают голос сами.** Если пять минут ничего не происходит, кто-то
   пишет в чат — напоминает про подсказки, советует пройти по панелям по списку
   или просто подкалывает. На отметках 5, 10 и 14 находок приходит реакция на
   прогресс. Без этого чат оживал бы только по нажатию кнопки.

## 3. Архитектура стенда

Четыре контейнера, но **один образ с тремя ролями** — иначе три сборки Node на
каждый `--build`.

| Сервис | Порт | `APP_ROLE` | Роль |
| --- | --- | --- | --- |
| `public` | 8080 | `public` | лендинг + публичное API. Единственная ссылка для команды |
| `corp` | 7070 | `corp` | внутренний контур бота |
| `host` | 9090 | `host` | дашборд ведущего (React + antd). Только на `127.0.0.1` |
| `mongo` | — | — | состояние игры. Наружу **не публикуется** |

Порты разведены намеренно: `8080` и `8081` рядом путаются на глаз, а команда
всю игру сравнивает домены и порты в колонке Domain. `7070` ни с чем не
спутаешь.

MongoDB нужна ровно затем, чтобы случайный рестарт бэкенда посреди урока не
стёр сорок минут находок. В 02 порт базы публиковался — там это был инструмент
участника; здесь база служебная.

### Адреса: всё через env, ничего в хардкоде

IP стенда заранее неизвестен, поэтому ни один адрес не зашит в исходники.

| Переменная | Дефолт | Что делает |
| --- | --- | --- |
| `CORP_ORIGIN` | пусто | полный ориджин корп-контура. Пусто — собирается в рантайме |
| `CORP_PUBLIC_PORT` | `7070` | порт корпа, из которого собирается ориджин |
| `STAND_PUBLIC_HOST` | пусто | адрес паблика, если стенд за пробросом или под DNS-именем |
| `STAND_PUBLIC_PORT` | `8080` | порт паблика, из которого собирается адрес возврата |

Логика подстановки (паттерн `buildConnectionInfo` из 02): если `CORP_ORIGIN`
пуст, ориджин собирается из заголовка `Host` того запроса, которым открыли
страницу, плюс `CORP_PUBLIC_PORT`. Открыли `http://192.168.1.50:8080` — корп
станет `http://192.168.1.50:7070`, и ту же ссылку можно отдать команде как есть.

Подстановка происходит **при отдаче** HTML, CSS и JS: в шаблонах стоит
`{{CORP_ORIGIN}}`, ответ отдаётся с `Cache-Control: no-store`.

### Один адрес везде, косметического домена нет

Раньше стенд разводил две вещи: вычисленный `CORP_ORIGIN` для настоящих
запросов и косметический домен `corp.test.kz` для данных. Домен нигде не
резолвился, поэтому найденную в JSON или в base64 строку нельзя было открыть —
`ERR_NAME_NOT_RESOLVED`.

Сейчас везде стоит вычисленный `CORP_ORIGIN` (`http://192.168.1.50:7070`): и в
разметке, и в заголовках, и в полях JSON, и внутри base64 из localStorage, и в
комментарии карты исходников. **Любая из пятнадцати находок открывается в
соседней вкладке и отвечает настоящими внутренними данными** — а это половина
учебного эффекта.

Там, где по формату нужен host:port, а не URL, используется `corpHost()` — тот
же адрес без схемы (`X-Corp-Host`, `X-Upstream-Addr`).

Имена нод остались именами: `rdb-corp-node04` — это имя машины, а не адрес, и
рядом с ним отдельным заголовком едет `X-Upstream-Addr`.

На зачёт это не влияет: **ответом всегда является путь, а не хост**. Ввели
полный URL с любым хостом — засчитано.

Побочный плюс живого корпа: cross-origin `fetch` даёт настоящий CORS-preflight.
Корп отдаёт `Access-Control-Allow-Origin: *` — часть халатности по легенде, и
это добавляет строк в Network.

### Стенд ничего не знает о реальном ReportDailyBot

Ни одного исходящего запроса за пределы docker-сети. Все адреса лендинга — либо
относительные пути, либо вычисленный `CORP_ORIGIN`. Настоящий проект дал только
легенду: название, тематику и вид лендинга.

### Сборка

**Лендинг — не React.** Кислотный маркетинговый одностраничник на antd
неправдоподобен, а бандл фреймворка в мегабайт утопил бы поиск по Sources.
Лендинг — обычный сайт: HTML, CSS и TypeScript, который **бэкенд собирает
esbuild'ом при старте процесса**.

Собираются **два** бандла, и разница между ними — это утечка 11:

| Бандл | Карта исходников | Зачем |
| --- | --- | --- |
| `app.js` | нет | основной код. Строка из утечки 6 ищется только Ctrl+Shift+F |
| `legacy.js` | **есть** | забытый старый счётчик визитов, выложенный с исходниками |

Разделение принципиально: будь карта у основного бандла, она развернула бы и
`admin.ts` — и утечка 6 перестала бы существовать как отдельное упражнение. Оба
урока живут только порознь.

**Дашборд ведущего — React + Ant Design**, собирается Vite на этапе
`docker build` в **отдельный каталог**: попади он в паблик-сборку, команда нашла
бы список ответов прямо в Sources — в сценарии, весь смысл которого в том,
чтобы туда полезть.

### Никаких бинарных ассетов

Все картинки, включая анимацию, генерируются кодом как SVG (SMIL:
`<animateTransform>`). В репозитории нет ни одного `.gif` и `.jpg`, стенд не
зависит от интернета.

## 4. Реестр утечек

Пятнадцать точек. Активны всегда все: переключателя набора нет, ведущий просто
заканчивает урок, когда время вышло.

| # | Категория | Панель DevTools | Слож. |
| --- | --- | --- | --- |
| 1 | HTML Form Action | Elements | ★ |
| 2 | Скрытый элемент UI | Elements + Styles | ★★ |
| 3 | Медиа с корп-хоста | Network → Img | ★★ |
| 4 | LocalStorage | Application → Local Storage | ★★ |
| 5 | Прямой API-запрос | Network → Fetch/XHR | ★★ |
| 6 | Хардкод в JS-бандле | Sources + Ctrl+Shift+F | ★★★ |
| 7 | Runtime Config | Console | ★ |
| 8 | HTTP Redirect | Network + Preserve log | ★★★ |
| 9 | Over-fetching | Network → Response | ★★ |
| 10 | HTTP-заголовки | Network → Headers | ★★ |
| 11 | Source map | Sources | ★★★ |
| 12 | Мета-теги сборки | Elements → `<head>` | ★ |
| 13 | Cookie | Application → Cookies | ★★ |
| 14 | robots.txt | прямой запрос | ★ |
| 15 | Ошибка в консоли | Console | ★★ |

Полное описание каждой — что именно оставлено, что видит команда, чему учит и
чем грозит — в [SABOTAGE.md](SABOTAGE.md). Исходник реестра, включая тексты
подсказок, — `backend/src/internal/leaks/registry.ts`.

### Независимость

Все утечки независимы, порядок любой, домино нет. Мягкие связи:

- **6 и 7** обе про JS: открывший Sources ради одной чаще находит вторую;
- **8 и 12** обе требуют Preserve log, но с разных сторон — переход и уход;
- **11** ломала бы 6, если бы карта висела на общем бандле (см. раздел 3);
- **15** видна и в Console, и красным в Network — двойной путь намеренно.

## 5. Механика зачёта

### Одно поле, автоопределение

Ведущий вставляет продиктованную строку в единственное поле — без выбора
категории. Система сама определяет, какая это из пятнадцати, и открывает строку
в таблице.

**В зачёт идёт адрес, а не токен.** Поле так и просит: «вставьте найденный
адрес». Токены и имена нод, которые команда встретит по дороге, — это
доказательство утечки, а не сама утечка: их называют вслух на разборе. Приняты
они всё-таки будут (колонка «страховка» ниже) — спорить с Капитаном посреди
урока о форме ответа хуже, чем засчитать соседнюю строку.

### Маркеры

| # | Канонический ответ | Страховка |
| --- | --- | --- |
| 1 | `/broadcast/subscribe-f2b7` | — |
| 2 | `/owner/console-9d4c` | — |
| 3 | `/static/serverroom-3e8a.svg` | без расширения |
| 4 | `/report/send-recent-b51e` | `tg_bot_5f31c7` |

Три правила, которым обязан удовлетворять любой маркер:

1. **Неугадываемость.** В каждом фиксированный, но случайный на вид сегмент
   (`f2b7`, `b51e`, `7c19`). Перебором не берётся.
2. **Ни один маркер не является подстрокой другого.** Иначе одна находка
   закрывала бы две. У 4, 5, 6 и 15 общий префикс `/report/`, но хвосты разные.
3. **Диктуемость вслух.** Латиница и цифры, без спецсимволов.

Адрес контура сам по себе не засчитывается никогда — он светится в
большинстве утечек и не указывает ни на одну конкретную.

### Нормализация

Ввод приводится к канону последовательно: `trim` → нижний регистр → удаление
кавычек, пробелов и обратных слэшей → удаление схемы → удаление хоста с портом
→ отсечение query и hash → удаление крайних слэшей. Полный URL, голый путь и
строка с кавычками из JSON дают один результат.

### Осмысленные отказы

| Ввод | Ответ дашборда |
| --- | --- |
| голый хост (`192.168.1.50:7070`) | «это хост, а не точка утечки — назовите конкретный адрес» |
| слишком общий путь (`/report/`) | «слишком общо, нужен полный адрес» |
| уже найденное | «это утечка №N, она уже засчитана» |
| всё остальное | «не совпало» |

Брутфорса можно не бояться: неугадываемый сегмент делает перебор бессмысленным.

глобальный поиск в Sources становится единственным рабочим способом, и именно
этому учит кейс 6. Гнаться за «как в проде» незачем: в бандле только настоящий

там участник имел доступ к базе и наткнулся бы на спойлеры.

Правило стенда: **репозиторий целиком — спойлер**. Команда его не открывает.

├─ docker-compose.yml         # public 8080 + corp 7070 + host 9090 + mongo
├─ .env / .env.example        # только адреса и подключение к базе
├─ frontend/
│  ├─ site/                   # лендинг: index.html, styles.css, src/*.ts
│  │  └─ src/legacy/          #   старый бандл, который отдаётся с картой

│  ├─ Dockerfile              # 2 стадии: сборка дашборда -> образ бэкенда
│  └─ src/
│     ├─ main.ts              # выбор роли по APP_ROLE
│     ├─ public/              # лендинг, публичное API, заголовки и cookie
│     ├─ corp/                # внутренний контур
│     ├─ host/                # API дашборда и его страница
│     └─ internal/            # СПОЙЛЕР
│        ├─ leaks/registry.ts #   реестр: маркеры, уроки, опасность, подсказки
│        ├─ site/             #   сборка двух бандлов и генерация SVG
│        ├─ game/             #   состояние игры
│        ├─ feed/             #   чат #security и тексты
│        └─ lib/              #   origin, normalize, envelope, mongo

`internal/leaks/registry.ts` — единственный источник правды: из него строится
сайт и по нему же проверяются ответы. Спойлер в чистом виде, как
`install/breakage.ts` в 02.

Переиспользуется из 02 без изменений: конверт ответов (`envelope.ts`), тёмная
палитра и раскладка 100vh дашборда, вычисление адреса из заголовка `Host`,
двухстадийный Dockerfile.

## 9. Запуск

```bash
cd scenarios/03-devtools-forensics
cp .env.example .env
docker compose up --build
```

| Что | Адрес | Кому |
| --- | --- | --- |
| Лендинг | `http://<ip>:8080` | **команде — только эту ссылку** |
| Внутренний контур | `http://<ip>:7070` | никому не сообщается, находится сам |
| Дашборд ведущего | `http://localhost:9090` | ведущему, только с машины стенда |

Дашборд без пароля, но и не виден из сети: порт 9090 опубликован на
`127.0.0.1`, а не на `0.0.0.0`, как паблик и корп. Команда сидит в одной сети с
ведущим — на `0.0.0.0` любой, кто подобрал бы порт, получил бы все ответы
разом. Пароль такой защиты не заменяет и не нужен: дашборд открывается только с
той машины, где поднят стенд. Спойлерить ему при этом всё равно нечем —
ненайденные категории и маркеры на клиент не уезжают вообще.

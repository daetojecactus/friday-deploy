# Правила урока

## Цель

Найти все точки утечки внутренних адресов на публичном лендинге ReportDailyBot.
Всего их пятнадцать. Готово — это когда все пятнадцать лампочек зелёные и в чате
`#security` финальное сообщение от тимлида.

Страница команды — `http://<ip>:8080`. Больше адресов вам не дают: остальное
находится само.

## Как работаем

1. Работаем по очереди.
2. Решения принимает и диктует Капитан.
3. **Ищем только в браузере.** Chrome DevTools — единственный инструмент.
   `curl` разрешён, когда захочется проверить найденный адрес руками.
4. **Репозиторий стенда не открываем и не клонируем.** В нём лежит и лендинг с
   утечками, и список ответов открытым текстом. Это не «нечестно» — это просто
   конец игры.
5. **Ничего не чиним.** Ни кода, ни конфигов: задача найти, а не исправить.
6. Нашли — говорите вслух. Ведущий вводит адрес и зачитывает разбор.

## Что считается находкой

**Адрес** внутреннего контура, найденный на публичной странице. Форма записи
любая — полный URL, голый путь, строка с кавычками из JSON: всё нормализуется.

Не засчитывается:

- **имя домена само по себе.** Оно встречается почти в каждой утечке и не
  указывает ни на одну конкретную;
- **общий префикс пути** без хвоста. Дашборд скажет «слишком общо» — значит,
  направление верное, дожимайте.

Токены и имена серверов по дороге попадутся — они не ответ, а доказательство.
Называйте их вслух на разборе, в зачёт идёт адрес.

## Подсказки

Три уровня на каждую утечку. Просите — ведущий напишет в рабочий чат от вашего
имени, ИБ ответит:

1. **Когда видно** — при загрузке, после действия, при уходе со страницы или
   вообще никогда в Network.
2. **Какая панель** — Elements, Network, Application, Console, Sources.
3. **Что смотреть** — почти ответ.

Подсказки не штраф: они отмечаются в таблице, чтобы на разборе было видно, где
команда встала. Берите, если буксуете больше пяти минут.

## Диагностический набор

### Панели и что в них искать

```
Elements     разметка целиком, включая то, чего нет на экране
             панель Styles: почему элемент есть, а не виден
             тег <head>: туда сборка тоже что-то пишет
Network      фильтры Fetch/XHR · Img · CSS · Doc
             колонка Domain: какой запрос ушёл не на этот сайт
             вкладки Headers и Response — это разные места
             галочка Preserve log: без неё переход стирает лог
             красные строки: упавший запрос — тоже след
Application  Local Storage, Session Storage, Cookies
Console      то, что уже написано, плюс Object.keys(window) и atob()
Sources      дерево файлов и Ctrl+Shift+F — поиск по всем файлам сразу
```

### Команды, если хочется проверить руками

```bash
# страница и её статика
curl -s  http://<ip>:8080/ | less
curl -s  http://<ip>:8080/assets/styles.css
curl -s  http://<ip>:8080/assets/app.js

# заголовки и cookie
curl -sI http://<ip>:8080/
curl -sI http://<ip>:8080/api/stats

# публичное API: смотреть тело целиком
curl -s  http://<ip>:8080/api/reviews | python3 -m json.tool

# цепочка переходов
curl -sIL http://<ip>:8080/api/promo/mega | grep -iE 'HTTP/|location'

# файлы, которые есть у любого сайта
curl -s  http://<ip>:8080/robots.txt
```

## Ориентиры

- **Каждая утечка живёт в своей панели.** Если в какой-то панели вы ещё не были —
  почти наверняка там что-то есть.
- **Смотрите не только на то, что нарисовано.** Ответ API может содержать больше,
  чем показывает интерфейс; элемент может быть в разметке и не быть на экране.
- **Заголовки и cookie — это тоже ответ.** Их видно ровно так же, как тело.
- **Не всё, что видно, вызывается.** Строка может лежать в бандле и не попадать
  в Network ни при каком действии.
- **Не всё, что вызывается, видно.** Без Preserve log переход и уход со страницы
  уносят с собой историю запросов.
- **Упавший запрос — это след.** Красная строка в Network и предупреждение в
  Console обычно говорят об одном и том же.
- **У сайта есть файлы, которых нет на странице.** По фиксированным адресам, и
  открыть их может кто угодно.
- **Домен — не ответ.** Он есть почти везде. Нужен конкретный адрес.
- Полный контекст стенда — в [CONTEXT.md](CONTEXT.md), но читать его до конца
  игры не надо: там спойлеры.

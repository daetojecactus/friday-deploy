# internal/ — служебный слой стенда

⚠️ **Спойлер.** Здесь лежит не приложение, а обвязка тренажера: установщик,
поломки, синтетический мониторинг и тексты Slack-ленты. Участнику сюда
заглядывать нельзя — в `install/breakage.ts` прямым текстом написано, что
сломано и как это чинится.

```
internal/
├─ platform.ts        # префикс /api, конверт ответов, статика, старт стенда
├─ stand.controller.ts# /api/stand/status и /api/stand/reset
├─ install/           # ЭТАЛОН и ПОЛОМКИ
│  ├─ schema.ts       #   валидаторы и индексы такими, какими они должны быть
│  ├─ data.ts         #   детерминированные демо-данные
│  ├─ breakage.ts     #   семь поломок: что портим и как чинится
│  └─ index.ts        #   однократная установка + переустановка
├─ probes/            # синтетический мониторинг: семь бизнес-проб раз в 5 с
├─ feed/              # Slack-движок и тексты сообщений
└─ lib/
   ├─ mongo.ts        #   подключение приложения (crm_app, readWrite)
   ├─ admin.ts        #   root-подключение установщика + база stand_meta
   └─ envelope.ts     #   { ok, data } / { ok, error } с сырой ошибкой MongoDB
```

Два правила, на которых держится стенд:

1. **Приложение не создает индексов и не знает схемы.** Схема, индексы и
   валидаторы живут только в MongoDB, поэтому починка через `mongosh`
   применяется мгновенно и ничем не перетирается.
2. **Установка выполняется один раз.** Маркер лежит в базе `stand_meta`, к
   которой у участника нет доступа. Рестарт бэкенда не трогает ни данные, ни
   починки; переустановка — только через `POST /api/stand/reset`.

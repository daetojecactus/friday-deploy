# Healthcheck Debug

Командный тренажер по траблшутингу. Дашборд из 10 healthcheck'ов: каждый —
зеленый или красный индикатор с текстом ошибки. Ведущий ломает часть проверок
заранее, команда чинит их по очереди. Цель — сделать все индикаторы зелеными.

Один `docker-compose up` поднимает живую песочницу: PostgreSQL, Redis, имитацию
внешнего вендора и «падающих» сервисов, а также эффект домино между проверками.

## Стек

- **Backend** — NestJS (TypeScript), REST. Отдает фронтенд и имитирует внешние системы.
- **Инфраструктура** — Docker Compose: backend + PostgreSQL + Redis (3 контейнера).
- **Frontend** — одна HTML-страница на чистом JS, поллинг `/api/checks` раз в 3 секунды.

## Быстрый старт

```bash
cp .env.example .env
docker-compose up --build
```

Дашборд — http://localhost:8080. При эталонном `.env` все 10 проверок зеленые.

## Структура проекта

```
.
├─ docker-compose.yml             # 3 сервиса: backend, postgres, redis
├─ .env.example                   # эталонный конфиг (копируется в .env)
├─ .env                           # локальный конфиг (в репозиторий не попадает)
├─ frontend/index.html            # дашборд (vanilla JS, поллинг раз в 3с)
├─ backend/src/
│  ├─ main.ts                     # bootstrap, CORS, отдача статики
│  ├─ checks.controller.ts        # 10 health-проверок — то, что чинят участники
│  ├─ app.module.ts               # регистрация контроллеров
│  └─ internal/                   # служебный код стенда — при отладке не нужен
│     ├─ index.ts                 # публичная точка входа для checks.controller
│     ├─ config.ts                # адреса: APP_PORT, HOST_URL, vendorUrl()
│     ├─ controllers/             # имитации внешних систем + агрегатор
│     ├─ checks/                  # CheckResult, CHECK_NAMES, MESSAGES
│     └─ lib/                     # env, http, net, limiter
├─ RULES.md                       # правила урока и диагностические команды
└─ SABOTAGE.md                    # плейбук ведущего
```

Все, что чинится во время урока, лежит в `.env` и в `backend/src/checks.controller.ts`.
Папка `backend/src/internal/` — имитация чужих систем и служебная логика.

## Про пересборку

- Правки в `backend/src/` применяются сами за пару секунд (`tsx watch`).
- Правки в `.env` применяются сами за пару секунд (конфиг перечитывается на лету).
- Пересборка (`docker-compose up --build`) нужна только при изменении
  `docker-compose.yml`, `Dockerfile` или зависимостей в `package.json`.

## Список проверок

| #   | Проверка             | Симптом                                       | Где фикс |
| --- | -------------------- | --------------------------------------------- | -------- |
| 1   | `db_connection`      | Нет коннекта к БД (неверный хост)            | `.env`   |
| 2   | `redis_ping`         | Redis не отвечает (нужен пароль)             | `.env`   |
| 3   | `vendor_api_headers` | Ответ вендора не разобрать как JSON          | `src`    |
| 4   | `vendor_auth_scheme` | Вендор отвечает 401 (нет схемы `Bearer`)      | `src`    |
| 5   | `api_routing`        | Вендор отвечает 404 (захардкожена версия URL) | `src`    |
| 6   | `response_format`    | Опечатка в пути → 404 вместо JSON            | `src`    |
| 7   | `cors_headers`       | Нет CORS-заголовков в ответе                 | `src`    |
| 8   | `config_parsing`     | Порт из `.env` не приведен к числу (TypeError) | `src`  |
| 9   | `rate_limiter`       | 429 — домино после починки Redis (№2)        | `.env`   |
| 10  | `type_mismatch`      | Баланс вендора приходит строкой, а не числом | `src`    |

## Правила (кратко)

1. Работаем по очереди.
2. Решения принимает Капитан.
3. Правим только `backend/src/checks.controller.ts` и `.env`. Инфраструктуру — с
   согласия команды.

Полные правила и диагностические команды — в [RULES.md](RULES.md).

## Для ведущего

Проект собирается полностью рабочим. Перед стендапом сломайте нужные проверки по
плейбуку [SABOTAGE.md](SABOTAGE.md) — там для каждой указано, как сломать, как
починить и как проверить.

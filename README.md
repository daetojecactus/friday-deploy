# Friday Deploy — набор командных тренажёров по траблшутингу

Это набор мини-тренажёров для тех-стендапа. Каждый тренажёр («сценарий») —
самостоятельная песочница со своей задачей, своим стеком и своим
`docker-compose`.

Всё, что специфично для конкретного тренажёра — стек, легенда, порты, как
ломать и чинить — лежит внутри его папки. Корень репозитория про внутренности
сценариев ничего не знает.

## Сценарии

| #   | Папка                                                                  | Тема                                                                          | Стек                          |
| --- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------- |
| 01  | [`scenarios/01-healthcheck-debug/`](scenarios/01-healthcheck-debug/)   | Дашборд из 10 healthcheck'ов — сделать все зелёными                           | NestJS + PG + Redis + Mongo   |
| 02  | [`scenarios/02-mongodb-dubug/`](scenarios/02-mongodb-dubug/)           | Дежурная консоль CRM — семь бизнес-инцидентов, все причины внутри MongoDB     | NestJS + MongoDB + React/antd |
| 03  | [`scenarios/03-devtools-forensics/`](scenarios/03-devtools-forensics/) | Лендинг телеграм-бота — найти в браузере пятнадцать утечек внутренних адресов | NestJS + MongoDB + React/antd |

Новые сценарии добавляются как отдельные папки в `scenarios/` с собственным
`README.md` и `docker-compose.yml`. Стек может быть любым — Node, Python и т.д.

## Как запустить

Сценарии рассчитаны на запуск **по одному за раз**: порты у них пересекаются.

```bash
cd scenarios/<нужный сценарий>
cp .env.example .env
docker compose up --build
```

Адреса, порты и что открывать — в `README.md` внутри папки сценария.

## Документы сценария

У каждого тренажёра один и тот же набор:

| Файл | Кому | О чём |
| --- | --- | --- |
| `GUIDE.md` | команде | что происходит и что делать. Читается за пять минут |
| `RULES.md` | команде | правила урока и диагностические команды |
| `README.md` | ведущему | стек, структура, запуск |
| `CONTEXT.md` | ведущему | полное устройство стенда |
| `SABOTAGE.md` | **только ведущему** | что сломано или спрятано. Спойлер |

## Общие правила урока

1. Работаем по очереди.
2. Говорит и принимает решения только **Капитан**.
3. Правим только то, что относится к «нашей стороне». Инфраструктуру — с общего
   согласия команды. В некоторых сценариях не правят вообще ничего: точный
   список — в `RULES.md`.
4. `SABOTAGE.md` не открываем.
